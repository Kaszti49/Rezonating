# hackathon-rezon: the working fall detector (reference)

Snapshot of the fall detector built at the HARMAN Hackathon 2026 (13–14 Nov 2026), copied from
`Kaszti49/RezonFallDetector` at commit `f6d2eee`. It ran on the stage: one SM-24 geophone on an
ADC 15 Click (ADS131M02 + LTC6903), ESP32-S3 DevKit, speaker (I2S → PCM5102A → ZK-502M), SIM868
modem that phones for help, Bluetooth LE link to two web pages.

**Status: reference, not the node firmware.** It is an Arduino sketch (arduino-cli,
`esp32:esp32:esp32s3`, core 3.3.8). The node firmware stays ESP-IDF (`firmware/main`,
`firmware/components`). The plan is to port the portable detection core (`rezon/src/core/`, no
Arduino includes) into an ESP-IDF component as the `fall` pack's engine. Until that port is decided
and done, change nothing here except to keep it building; new work goes into the node firmware.

## What is where
| Path | What |
| --- | --- |
| `rezon/src/core/` | Portable C++ detection core: signal paths, events, feature vector, fall score, walker tracks, after-fall logic (`rezon_core`), alarm sequence (`rezon_alarm.h`), serial line format (`rezon_proto.h`), fitted weights (`rezon_weights.h`) |
| `rezon/rezon.ino` | ESP32-S3 glue: ADC, sampling task, LED, button, speaker, modem, BLE, settings in flash |
| `rezon/clips.h` | The two voice clips (16 kHz PCM), generated by `tools/mkclips.js` |
| `rezon/secrets.example.h` | Copy to `secrets.h` (git-ignored) for the phone number and SIM PIN |
| `tools/replay.cpp` | Feeds recordings through the core on the laptop and prints every event and decision |
| `tools/fit.cpp` | Fits the fall-score weights (class-balanced, L2, sign-constrained logistic regression, leave-one-recording-out) |
| `tools/build.*`, `train.bat`, `mixtest.sh` | Build the tools, re-fit the weights, synthetic walking-over-fall tests |
| `ui/live.html`, `ui/train.html` | Stage screen and recording/labelling page (Web Serial / Web Bluetooth, offline) |
| `data/labels.tsv` | Event labels (the first seven are provisional) |
| `practice/` | Bench sketches (ADC driver, modem call test and diagnostics) and the tuning page `geo_viz` |
| `MASTER_PROMPT.md` | The detection spec the core was built from |
| `NOTES.md` | The hackathon log from the SIM868 switch to the last flash: measurements, decisions, known weak points |

Hardware sources (wiring guide, parts list, casing STL and Blender scripts) are in `hardware/hackathon/`.

## Recordings
Recordings are never committed. Put them in `data/raw/hackathon/` at the repo root:
`geophone_2026-11-12T*.csv` (from the hackathon repo's `uploads/`) and `session_*.log`,
`demo_fall.log` (from its `firmware/data/`). `train.bat` and `mixtest.sh` read them from there.

## Check it
```sh
cd firmware/hackathon-rezon/tools
sh build.sh                       # or build.bat; needs g++ (MSYS2 ucrt64 on the home desktop)
./replay.exe --quiet --set stepMin=1.5 --set impactMin=6 --set walkerMargin=1.5 --set stepRef=8 \
  ../../../data/raw/hackathon/session_2026-11-14T01-41-28.log
```
Expected (checked 2026-11-15): `fall-shaped 3 ... alarm: calls 1`: the three labelled falls at
43.7, 51.5 and 60.4 s are found and the three jumps after them are not. The `--set` values are the
settings stored in the device's flash at the end of the hackathon; the compiled defaults differ.

## Known limits (from NOTES.md)
- Few labelled events: 3 stage falls, 3 jumps, 7 provisional falls. The fit proves little yet.
- Walker tracking is weak on soft-shoe steps, so bystander recognition rarely engages.
- A new walker who starts after a fall cancels it like someone getting up (one sensor cannot tell).
- The feature code exists only in C++; the Python side (`ml/`) has no matching implementation.
